SLAM 告诉你墙在哪里，场景理解进一步告诉你：这是墙、那是门、前方的人正在移动、这片地面可以走。对机器人来说，语义不是装饰，而是决策的依据——同样大小的障碍物，纸箱和玻璃门的风险完全不同。

本节的重点不是训练一个检测模型，而是理解从像素到动作的完整转换过程，以及每一步可能引入的误差。

## 1. 从几何到语义

典型感知链路如下：

```text
相机图像 ──> 目标检测 / 分割 ──> 像素区域
                                   │
深度图 / 点云 ──> 反投影 ──> 三维位置与尺寸
                                   │
                            跟踪 / 预测
                                   │
                          局部代价地图 / 风险
                                   │
                              路径规划
```

每一个箭头都可能出错：检测漏掉目标、深度估计不准、外参标定偏差、时间戳不同步、跟踪 ID 跳变、代价地图膨胀过大或过小。最终表现可能是“机器人莫名停下”或“机器人撞上透明物体”。

## 2. 检测与分割

目标检测输出边界框与类别，适合人、车辆、设备、标志等离散目标。语义分割输出逐像素类别，适合地面、草地、台阶、可通行区域。实例分割兼顾两者，但计算量更大。

常见工程选择：

- **YOLO 系列**：推理速度快，适合边缘部署，边界框精度受小目标与遮挡影响。
- **语义分割网络**：适合地形与可通行区域，但需要更多标注，边缘推理成本高。
- **传统几何方法**：用平面拟合、地面分割与聚类检测障碍，不依赖训练数据，适合作为兜底。

在安全相关场景中，建议保留几何兜底。深度学习模型可能对未见过的新物体失效，而几何障碍检测仍能发现“前方有东西”。

## 3. 从像素到三维

仅有边界框不足以规划。需要把像素位置转换为机器人坐标系下的三维位置：

1. 用相机内参把像素反投影为相机坐标系下的射线。
2. 结合深度值或激光点云，确定沿射线的距离。
3. 用外参把点变换到 `base_link` 或 `map` 坐标系。
4. 估计目标的尺寸、朝向与速度。
5. 写入代价地图或障碍列表。

如果深度缺失，可以用地面平面假设估计目标落点，但这只适用于目标在地面上的情况。对于悬空物体、台阶边缘和斜坡，平面假设会带来明显误差。

## 4. 可通行区域与代价地图

局部规划器通常消费一张代价地图。每个栅格的值表示通行代价，障碍物周围会做膨胀（inflation），为机器人保留安全距离。

膨胀半径过小，机器人可能贴得太近；过大，狭窄通道会被完全堵死。半径应根据机器人几何尺寸、定位误差与控制误差共同确定，而不是拍脑袋设一个固定值。

对于四足机器人，还可利用地形分析判断斜坡、台阶与松软地面。可通行不等于“几何上没有障碍”，还包括稳定性、抓地力与跌倒风险。

## 5. 动态环境

动态障碍物需要跟踪与预测。常见流程是多目标跟踪（如 Kalman 滤波或 SORT 类方法）为每个目标维持 ID 与速度，再预测短时未来位置。

工程上要特别关注：

- **延迟**：检测结果从采集到进入规划器可能超过 100 ms，快速目标的位置已经变化。
- **遮挡**：目标被遮挡后 ID 可能丢失，重新出现时被当作新目标。
- **误检**：反光、阴影和屏幕内容可能被误认为目标。
- **交互**：行人会主动避让机器人，预测模型应考虑这种耦合。

在动态环境中，保守策略往往比激进预测更安全：降低速度、增大安全距离、准备急停。

## 6. 评价与压力测试

| 指标 | 含义 | 适用 |
| --- | --- | --- |
| Precision / Recall | 误检与漏检的权衡 | 检测 |
| mAP | 多类别检测的综合精度 | 检测 |
| IoU | 分割区域重叠程度 | 分割 |
| 端到端延迟 | 从采集到决策输入的时间 | 系统 |
| 漏检代价 | 漏掉关键障碍的后果 | 安全 |

不要只看 mAP。巡检场景中，漏掉一个台阶可能比误检一只鸟更严重。应根据任务定义加权指标，并设计压力测试：强光、逆光、雨雾、夜间、快速运动、遮挡、透明物体、未知类别。

## 7. 边缘部署

机器人上的计算资源有限。常见优化包括：

- 模型量化（FP16 / INT8）与 TensorRT 加速。
- 输入分辨率与推理频率的权衡。
- 多线程流水线，把采集、推理与后处理重叠。
- 结果缓存与跟踪，降低对单帧检测的依赖。
- 监控温度与丢帧，避免性能在长时间运行后下降。

量化会改变数值精度，部署前必须在真实数据上重新评估，而不能只看桌面 GPU 的 benchmark。

> 工程提示：给感知链路加一个“健康检查”话题，报告帧率、延迟、检测数量与异常状态。规划器可以根据健康状态降速或停车，而不是盲目使用过期数据。

## 8. 从检测到规划的安全接口

感知结果进入规划器前，应经过一层明确的接口：

```text
检测结果
  → 时间戳有效性检查
  → 坐标系转换
  → 尺寸与位置合理性检查
  → 置信度与健康状态
  → 障碍列表 / 代价地图
```

如果检测结果过期，规划器应使用保守策略，而不是继续消费旧数据。可以给每个障碍附加“有效期”与“置信度”，让局部规划器根据风险调整速度。

对安全关键障碍，建议保留几何检测作为独立通道。学习模型与几何方法同时报告障碍时，取更保守的结果；两者冲突时，记录冲突并触发人工复核或降速。

## 本节小结

- 场景理解把几何地图转化为可决策的语义与风险信息。
- 从像素到三维需要内参、深度、外参与时间同步的共同支持。
- 代价地图的膨胀半径应服从机器人几何与控制误差。
- 动态环境要处理延迟、遮挡与误检，保守策略往往更安全。
- 评价应关注端到端延迟与漏检代价，而不只是 mAP。
