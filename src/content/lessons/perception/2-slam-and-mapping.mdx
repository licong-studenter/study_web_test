SLAM（Simultaneous Localization and Mapping）要同时回答两个互相依赖的问题：机器人在哪里？地图长什么样？知道位姿才能把观测拼成地图，有了地图才能更准确地定位。这个循环看起来像“鸡生蛋”，实际通过概率估计与优化同时求解。

对四足机器人而言，SLAM 的难点还在于身体会起伏、转向和冲击。相机会抖，激光雷达会运动畸变，IMU 会饱和。一个在手持设备上稳定的算法，搬到机器狗上可能需要重新设计同步与补偿。

## 1. SLAM 的三个核心模块

### 1.1 前端：帧间配准

前端负责从相邻观测中估计相对运动。激光 SLAM 通过点云配准（如 ICP 及其变体）估计位姿；视觉 SLAM 通过特征点匹配、光流或直接法估计相机运动；多模态方案则结合 IMU 预积分与视觉 / 激光观测。

前端追求实时性与局部一致性，但会累积漂移。快速运动、弱纹理、动态物体和传感器噪声都可能导致配准失败。

### 1.2 后端：全局优化

后端把一段时间内的位姿与观测组织成因子图，通过最小化残差得到全局一致的轨迹与地图：

$$ \min_{\{x_i\}} \sum_{(i,j)\in\mathcal{E}} \left\| e_{ij}(x_i, x_j, z_{ij}) \right\|^2_{\Omega_{ij}} $$

其中 $x_i$ 是位姿，$z_{ij}$ 是观测约束，$e_{ij}$ 是残差，$\Omega_{ij}$ 是信息矩阵。后端可以运行得比前端慢，但必须能在回环发生时快速修正全局轨迹。

### 1.3 回环检测

回环检测判断机器人是否回到曾经去过的地方。一旦检测到回环，就可以加入一条长距离约束，显著降低累积漂移。误检回环会破坏地图，因此需要几何验证与鲁棒核函数。

## 2. 激光、视觉与多模态

| 方案 | 优势 | 局限 | 适用场景 |
| --- | --- | --- | --- |
| 激光 SLAM | 几何精确、受光照影响小 | 雨雾、玻璃、运动畸变 | 室内、园区、结构化环境 |
| 视觉 SLAM | 信息丰富、成本低 | 弱纹理、光照变化、尺度漂移 | 纹理丰富、光照可控 |
| 视觉惯性 | 尺度可观测、动态响应好 | 标定敏感、快速运动易失败 | 手持、无人机、机器人 |
| 激光惯性视觉 | 互补性强、鲁棒性高 | 系统复杂、同步要求高 | 复杂户外、建图与导航 |

选择方案时，应先明确场景约束，而不是追求“最先进”。一个在室内结构化环境中稳定的激光 SLAM，可能比复杂多模态系统更适合巡检任务。

## 3. FAST-LIVO2 在 Lite3 上的实践

`fast-livo2-deep-robotics` 仓库记录了在 Lite3 上复现 FAST-LIVO2 的过程。根据其 README：

- 系统环境为 Ubuntu 22.04、ROS 2 Humble。
- 测试平台为 Lite3 Venture，搭载 AGX Jetson Orin（或类似板载算力）。
- 仓库提供 `main` 与 `soft-sync` 两个分支：硬件同步或使用公开数据集时用 `main`；IMU、激光与相机时钟不同步时使用 `soft-sync`。
- README 提到，若时钟不同步且不做软同步，SLAM 可能在约 20 秒后失败。

这些细节说明，SLAM 的成败往往不在“算法公式”，而在时间同步、外参标定、传感器安装与计算平台。部署前应逐项确认：

1. 传感器是否支持硬件同步？触发信号如何连接？
2. 若只能软同步，时间戳偏移如何估计与补偿？
3. 外参是否标定？安装后是否发生位移？
4. 计算平台是否满足实时性？点云与图像处理是否掉帧？
5. 地图坐标系与导航坐标系如何对齐？

## 4. 地图表示

不同任务需要不同地图：

- **点云地图**：保留几何细节，适合定位与可视化，但数据量大。
- **占据栅格地图**：把空间离散为可通行 / 不可通行，适合路径规划。
- **ESDF / 距离场**：提供到最近障碍的距离与梯度，适合局部避障。
- **语义地图**：在几何地图上叠加物体类别与区域属性，适合任务规划。

地图不是越精细越好。导航更关心可通行性与更新频率，定位更关心几何一致性。系统设计时应明确每种地图的消费者与更新策略。

## 5. 评价 SLAM 的指标

| 指标 | 含义 | 注意点 |
| --- | --- | --- |
| 绝对轨迹误差 ATE | 估计轨迹与真值的全局偏差 | 需要真值或高精度参考 |
| 相对位姿误差 RPE | 固定时间间隔内的相对运动误差 | 反映局部漂移 |
| 地图一致性 | 墙面、地面是否重影 | 受回环与优化影响 |
| 实时性 | 单帧处理时间、丢帧率 | 关注最坏情况 |
| 鲁棒性 | 快速运动、弱纹理、动态物体下的成功率 | 需要设计压力测试 |

只在一条平缓走廊上跑通，不能证明 SLAM 可用。应覆盖急转弯、快速运动、光照变化、动态行人与传感器短暂失效。

> 工程提示：建图前先确认 `map → odom → base_link` 的变换关系与更新频率。很多“地图漂移”问题，实际是坐标变换链配置错误。

## 6. 图优化与回环

因子图把每个位姿看作节点，把里程计、视觉、激光与回环观测看作边。优化时，系统寻找一组位姿，使所有边的残差加权平方和最小。信息矩阵决定每条观测的可信度：高精度激光约束权重更大，漂移严重的里程计权重更小。

回环检测通常分为两步：先找候选，再做几何验证。候选可以通过词袋、扫描上下文或描述子匹配获得；几何验证则确认两帧观测是否真的对应同一地点。误回环会让整张地图变形，因此需要鲁棒核函数与外点剔除。

回环发生时，后端可能需要重新优化整个轨迹。为避免计算量爆炸，系统通常使用滑动窗口、局部地图或增量式优化。工程上要关注回环后的地图更新是否会阻塞实时定位。

## 7. 地图评估方法

没有真值时，可以用一致性指标评估地图：

- 同一面墙在不同时间观测下是否重合。
- 回到起点后，轨迹是否闭合。
- 地面与墙面法向是否稳定。
- 动态物体是否被错误写入地图。

有真值时，则使用 ATE、RPE 与地图覆盖率等指标。评估时应覆盖不同速度、光照与场景，而不是只选一条最容易的路线。

## 本节小结

- SLAM 由前端配准、后端优化与回环检测构成，目标是同时估计轨迹与地图。
- 激光、视觉与多模态方案各有边界，选择应服从场景约束。
- FAST-LIVO2 的部署高度依赖硬件同步、外参与算力，README 中的限制必须认真对待。
- 地图表示应服务于具体消费者，评价应覆盖精度、实时性与鲁棒性。
