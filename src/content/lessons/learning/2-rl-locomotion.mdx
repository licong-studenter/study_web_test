手工设计步态需要工程师逐项调参，而强化学习把“如何控制”交给优化：策略在大量试错中最大化累计奖励。它特别适合那些难以精确建模的部分——复杂地形、接触不确定性、身体与环境的强耦合。

但强化学习不是“设置一个奖励，然后等待奇迹”。奖励设计、观测选择、动作空间、随机化范围与训练课程，都会决定策略学到的是你真正想要的行为，还是一个钻奖励空子的怪招。

## 1. 把行走写成 MDP

四足行走可以写成马尔可夫决策过程：

- **状态 / 观测**：身体线速度、角速度、重力方向、关节角、关节速度、上一帧动作、足端接触、地形高度等。
- **动作**：通常输出 12 个关节的目标位置偏移，由底层 PD 控制器跟踪；也可以输出力矩。
- **奖励**：鼓励前进、保持姿态、减少能耗、平滑动作、抬脚足够高。
- **终止**：身体倾斜过大、高度过低、越界或超时。

观测设计的关键是“可部署”：训练时用到的每个量，部署时都必须能实时获得，并且顺序、单位、归一化方式一致。

## 2. 策略、价值与优势

策略 $\pi_\theta(a \mid o)$ 给出在观测 $o$ 下选择动作 $a$ 的概率。价值函数 $V_\phi(o)$ 估计从当前观测出发的期望回报。优势函数衡量某个动作比平均水平好多少：

$$ \hat{A}_t = \sum_{k=0}^{T-t} \gamma^k r_{t+k} - V_\phi(o_t) $$

优势为正，说明这个动作值得增加概率；为负，则应该降低。策略梯度方法的核心，就是用优势加权更新策略。

## 3. PPO 的裁剪目标

PPO（Proximal Policy Optimization）通过限制每次更新的策略变化，避免训练崩溃。其裁剪目标为：

$$ L^{CLIP}(\theta) = \mathbb{E}\left[\min\left(r_t(\theta)\hat{A}_t,\ \operatorname{clip}(r_t(\theta),1-\epsilon,1+\epsilon)\hat{A}_t\right)\right] $$

其中：

$$ r_t(\theta) = \frac{\pi_\theta(a_t \mid o_t)}{\pi_{\theta_{old}}(a_t \mid o_t)} $$

当新旧策略差异过大时，裁剪项会阻止目标继续增长。$\epsilon$ 通常取 0.1–0.2。PPO 还需要价值损失、熵正则与梯度裁剪，具体权重需要根据任务调整。

PPO 的优点是实现相对简单、训练稳定；缺点是样本效率不如一些离线或模型方法，且对奖励尺度敏感。

## 4. 奖励设计

一个可用的行走奖励通常包含以下项：

| 奖励项 | 目的 | 常见形式 |
| --- | --- | --- |
| 速度跟踪 | 跟随指令速度 | $-\|v_{xy}-v^{ref}_{xy}\|^2$ |
| 姿态保持 | 保持身体水平 | $-\|\text{projected gravity}_{xy}\|^2$ |
| 高度保持 | 维持身体高度 | $-\|z-z^{ref}\|^2$ |
| 能耗惩罚 | 减少力矩 / 功率 | $-\sum \tau_i^2$ |
| 动作平滑 | 减少抖动 | $-\|a_t-a_{t-1}\|^2$ |
| 足端抬升 | 避免拖脚 | 对低于阈值的足端高度惩罚 |
| 接触约束 | 控制支撑相 | 对非预期接触惩罚 |

奖励权重需要平衡。速度奖励过强，策略可能牺牲姿态与能耗；平滑惩罚过强，策略可能变得迟钝。建议先让机器人“站稳”，再加入速度跟踪，最后加入地形与扰动。

## 5. Isaac Lab 训练流程

官方 `rl_training` 仓库提供了 Lite3 的训练环境，环境 ID 为 `Rough-Deeprobotics-Lite3-v0`。README 中标注的依赖包括 Isaac Sim 5.1.0、Isaac Lab 2.3.2、RSL-RL 5.0.1、Python 3.11 与 Ubuntu 22.04，实际版本以仓库为准。

一个概念性的训练流程：

```bash
# 1. 安装 Isaac Lab 与依赖（按官方文档）
# 2. 进入训练仓库
cd rl_training

# 3. 启动训练（具体脚本以仓库 README 为准）
python scripts/train.py \
  --task Rough-Deeprobotics-Lite3-v0 \
  --num_envs 4096 \
  --headless
```

训练时应监控：

- 平均回报与回合长度。
- 速度跟踪误差、姿态误差、能耗。
- 策略熵与价值损失。
- 视频中的步态是否自然。
- 不同随机种子下的稳定性。

## 6. 常见失败模式

| 现象 | 可能原因 | 应对 |
| --- | --- | --- |
| 回报上升但步态怪异 | 奖励被钻空子 | 增加姿态、能耗、接触约束 |
| 训练早期全部终止 | 初始状态过难 | 课程学习、降低初始扰动 |
| 后期性能崩溃 | 学习率过大、优势估计不稳 | 降低学习率、检查价值损失 |
| 仿真好、真机差 | 观测 / 动作不一致、随机化不足 | 对齐接口、系统辨识、增加随机化 |
| 只会直线走 | 指令分布单一 | 增加速度、转向与地形课程 |

强化学习调试的核心是“可解释地比较”。每次只改变一个因素，保存配置、曲线与视频。不要同时调整奖励、网络与随机化，否则无法判断因果。

> 工程提示：先训练一个能在平地稳定站立的策略，再逐步加入速度、转向与地形。一个连站立都不稳的策略，很难通过调参突然学会跑酷。

## 7. PPO 的实现细节

PPO 的效果不仅取决于公式，还取决于实现细节：

- **优势归一化**：对每个 batch 的优势做标准化，能稳定更新幅度。
- **价值裁剪**：限制价值函数更新，避免 critic 剧烈变化。
- **学习率调度**：训练后期降低学习率，减少策略震荡。
- **梯度裁剪**：防止异常 batch 造成参数爆炸。
- **并行环境**：增加样本多样性，但要注意每个环境的随机种子。

训练时应同时观察策略损失、价值损失、熵与近似 KL。若 KL 突然飙升，说明更新步长过大；若熵迅速降到接近零，策略可能过早收敛。

## 8. 奖励调试案例

假设策略学会了“原地高频抖动”来获得速度奖励。原因可能是奖励只看平均速度，而抖动让瞬时速度反复超过目标。解决方法包括：

- 惩罚动作变化率与关节加速度。
- 使用低通滤波后的速度计算奖励。
- 增加姿态与足端接触约束。
- 在评估时使用平滑后的轨迹指标。

另一个常见问题是“拖脚行走”。策略发现抬脚会消耗能量，于是贴着地面滑动。可以增加足端离地高度奖励或对非支撑相的低足端高度进行惩罚。

奖励调试的本质，是把工程目标翻译成可测量的信号，并不断检查策略是否在利用漏洞。

## 本节小结

- 四足行走可以写成以观测为输入、关节目标或力矩为输出的 MDP。
- PPO 用裁剪目标限制策略更新幅度，提升训练稳定性。
- 奖励设计要平衡速度、姿态、能耗、平滑与接触，避免奖励钻空子。
- 课程学习、随机化与严格接口对齐，是 Sim-to-Real 成功的关键。
