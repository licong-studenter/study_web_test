具身智能的数据与互联网文本有本质区别。一段文本可以独立存在，而一条机器人数据必须绑定时间、身体状态、动作与环境后果。脱离这些上下文，动作就失去了意义。

更麻烦的是，真实机器人数据昂贵且危险：每一次摔倒都可能损坏设备，每一次实验都需要人力和场地。仿真因此成为主要数据来源，但它必须足够接近现实，否则训练出的策略只是在拟合一个虚拟世界。

## 1. 一条数据样本包含什么

| 字段 | 含义 | 常见问题 |
| --- | --- | --- |
| timestamp | 采集时间 | 时钟不同步、时间戳缺失 |
| observation | 关节角、IMU、图像、点云等 | 顺序不一致、归一化错误 |
| action | 关节目标、力矩或速度指令 | 单位不一致、延迟未记录 |
| reward | 任务奖励（如适用） | 奖励与真实目标不一致 |
| done / truncation | 回合结束标志 | 超时与失败未区分 |
| metadata | 模型版本、场景、参数、随机种子 | 缺失导致无法复现 |

如果数据要用于训练策略，观测与动作的顺序必须在训练和部署时完全一致。一个常见的部署事故是：训练时关节顺序为 `FL, FR, RL, RR`，部署时变成 `FR, FL, RR, RL`，模型输出完全错乱。

## 2. 真实数据与仿真数据

| 来源 | 优势 | 局限 | 适用 |
| --- | --- | --- | --- |
| 真机采集 | 真实物理、真实噪声 | 昂贵、危险、规模有限 | 微调、验证、系统辨识 |
| MuJoCo | 轻量、接触稳定、易调试 | 渲染与传感器仿真有限 | 控制器验证、sim-to-sim |
| Isaac Sim / Lab | 高保真、GPU 并行、传感器丰富 | 配置复杂、显存需求高 | 大规模强化学习 |
| 公开数据集 | 成本低、可复现 | 场景与本体可能不匹配 | 预训练、算法对比 |

真实数据不一定“更高级”。如果采集过程缺少同步、标定与元数据，它的价值可能不如一份组织良好的仿真数据。关键是数据是否支撑你要回答的问题。

## 3. 并行仿真

强化学习需要大量交互样本。Isaac Lab 可以在 GPU 上并行运行成百上千个环境，把原本需要数天的采样压缩到数小时。并行化的关键不只是“数量”，还包括：

- 每个环境独立随机化初始状态。
- 观测与奖励在批量维度上高效计算。
- 训练与采样流水线重叠，避免 GPU 空转。
- 定期评估确定性策略，避免只看训练奖励。

并行环境数量受显存与 CPU 限制。盲目增大数量可能导致每个环境的时间步变慢，整体吞吐反而下降。

## 4. 域随机化

域随机化（Domain Randomization）在训练时随机变化物理参数与观测条件，让策略学会在分布变化下保持鲁棒：

- 质量、质心与惯量。
- 摩擦系数、接触刚度与阻尼。
- 电机增益、延迟与噪声。
- 地形高度、坡度与纹理。
- 传感器噪声、丢帧与外参微扰。

随机化范围不是越大越好。范围过大，策略会变得过度保守；范围过小，又无法覆盖真实差异。较好的做法是先做系统辨识，估计真实参数范围，再在此基础上留出合理裕度。

## 5. 系统辨识

系统辨识用真实数据估计仿真参数。一个简单流程：

1. 设计激励轨迹（正弦、阶跃、随机扰动）。
2. 在真机与仿真中执行相同指令。
3. 比较关节角、角速度、IMU 与足端接触。
4. 调整质量、摩擦、增益与延迟参数。
5. 用未参与辨识的轨迹验证。

系统辨识不需要完美匹配每一条曲线。目标是让关键动态特性（响应时间、超调、稳态误差、接触行为）落在可接受范围内。

## 6. 数据闭环

一个可持续的具身学习系统应形成闭环：

```text
仿真训练 ──> 策略评估 ──> 真机部署 ──> 失败样本
    ↑                                      │
    └──────── 数据回流 / 参数更新 <────────┘
```

失败样本尤其宝贵。它们揭示了策略的边界，也能指导下一轮随机化范围与奖励设计。只收集成功数据，会让模型越来越自信，却不知道自己的盲区。

> 工程提示：为每条数据记录模型版本与配置哈希。否则当你发现“这周效果变差”时，很难判断是数据、代码还是参数发生了变化。

## 7. 数据回放与标注

机器人数据不仅要采集，还要能回放与标注。ROS 2 的 rosbag2 可以记录话题数据，回放时应注意时间戳、QoS 与时钟源。回放速度可以加快，但涉及控制的实验应保持实时或明确标注时间缩放。

标注内容取决于任务：

- 感知：目标框、分割掩码、可通行区域。
- 控制：成功 / 失败、接触事件、扰动类型。
- 任务：子目标完成情况、人工接管点。

标注规范应提前定义，例如“什么算一次成功”“目标被遮挡多久算丢失”。否则不同标注者会给出不一致的数据，训练结果也难以解释。

## 8. 一次 Sim-to-Real 排查

当策略在仿真中表现良好、真机却失败时，可以按以下顺序排查：

1. **接口**：观测顺序、单位、归一化、动作缩放是否一致。
2. **时序**：控制频率、传感器延迟、通信抖动是否被模拟。
3. **模型**：质量、摩擦、力矩上限与关节零点是否匹配。
4. **状态机**：真机是否处于与仿真相同的控制模式。
5. **安全层**：限速、限幅或保护逻辑是否削弱了策略输出。

每次只验证一个假设，并记录结果。Sim-to-Real 不是一次性工作，而是持续的差异管理。

## 本节小结

- 具身数据必须绑定时间、观测、动作、结果与元数据。
- 仿真提供规模，真机提供真实约束，两者应形成闭环。
- 并行仿真提升采样效率，但受显存与调度限制。
- 域随机化与系统辨识共同决定 Sim-to-Real 的成败。
