仿真里的一条腿之所以能站起来，不是因为模型“看起来像”，而是因为质量、惯量、关节轴、碰撞几何与执行器参数共同构成了一个可信的动力学系统。模型错了，控制器再精细也只是拟合一个错误的物理世界。

本节从模型格式讲到实验设计。目标是让你能够判断：一个仿真结果是否值得相信，以及它与真机之间可能差在哪里。

## 1. 三种模型格式

| 格式 | 生态 | 优势 | 局限 | 典型用途 |
| --- | --- | --- | --- | --- |
| URDF | ROS / 通用机器人 | 结构清晰、工具链成熟 | 对接触、执行器与场景描述较弱 | 可视化、坐标变换、运动学 |
| MJCF | MuJoCo | 原生支持接触、执行器与传感器 | 与 ROS 生态需要转换 | 控制器验证、接触动力学 |
| USD | Isaac Sim / Omniverse | 场景、材质、物理与渲染统一 | 文件结构复杂、依赖生态 | 高保真仿真、合成数据 |

`deep_robotics_model` 同时提供 MJCF、URDF 与部分 USD 模型，这正好说明了一件事：同一种机器人可以在不同仿真器中以不同格式存在，但参数必须一致。转换格式时，关节轴、惯量与碰撞体最容易出错。

## 2. 模型由什么组成

一个机器人模型至少包含：

- **Link（刚体）**：质量、质心、惯量张量、视觉几何与碰撞几何。
- **Joint（关节）**：类型、轴、限位、阻尼、摩擦与零点。
- **Actuator（执行器）**：位置 / 速度 / 力矩控制模式、力矩上限、增益。
- **Sensor（传感器）**：IMU、关节编码器、相机、激光雷达。
- **Site / Frame（坐标点）**：足端、相机光心、工具中心点。

URDF 中的一段关节描述大致如下：

```xml
<joint name="FL_hip_joint" type="revolute">
  <parent link="base_link"/>
  <child link="FL_hip_link"/>
  <origin xyz="0.24 0.12 0.0" rpy="0 0 0"/>
  <axis xyz="1 0 0"/>
  <limit lower="-0.8" upper="0.8" effort="40" velocity="8"/>
</joint>
```

这段配置告诉仿真器：关节绕哪个轴旋转、允许多大角度、能输出多大力矩。任何一项与真机不一致，都可能导致控制效果差异。

## 3. MuJoCo：轻量、接触友好

MuJoCo 使用 MJCF，适合快速验证控制器与接触行为。一个概念性的模型结构如下：

```xml
<mujoco model="lite3">
  <compiler angle="radian"/>
  <option timestep="0.002" gravity="0 0 -9.81"/>

  <worldbody>
    <body name="base" pos="0 0 0.4">
      <freejoint/>
      <geom type="box" size="0.24 0.12 0.06"/>
      <!-- 四条腿的 body / joint / geom 省略 -->
    </body>
  </worldbody>

  <actuator>
    <!-- 每个关节的位置或力矩执行器 -->
  </actuator>
</mujoco>
```

关键参数包括：

- **timestep**：影响稳定性与计算量。太小会慢，太大会不稳定。
- **solref / solimp**：接触求解参数，影响脚与地面的软硬程度。
- **friction**：摩擦系数，直接决定打滑行为。
- **armature / damping**：模拟电机与减速器的惯性与阻尼。

仿真中的“脚底打滑”不一定是控制器问题，也可能是摩擦参数与接触求解设置不合理。

## 4. Isaac Sim / Isaac Lab：高保真与并行

Isaac Sim 基于 Omniverse 与 USD，提供高保真渲染、传感器仿真与 PhysX 物理。Isaac Lab 在其上提供强化学习环境接口，支持 GPU 并行训练。

官方 `rl_training` 仓库的 README 标注了 Isaac Sim 5.1.0、Isaac Lab 2.3.2、RSL-RL 5.0.1、Python 3.11 与 Ubuntu 22.04 等版本信息。这些版本会更新，实际环境应以仓库当前要求为准。

Isaac 的优势是规模：成百上千个环境并行采样，可以在数小时内获得大量交互数据。代价是配置复杂、显存占用高、仿真与现实之间仍存在差距。

## 5. 模型检查清单

在开始任何控制实验前，按以下清单检查模型：

| 检查项 | 常见问题 | 后果 |
| --- | --- | --- |
| 质量与惯量 | 单位错误、惯量缺失 | 步态异常、能量不守恒 |
| 关节轴 | 轴向与真机不一致 | 动作方向错误 |
| 关节限位 | 与实际范围不符 | 仿真可行、真机撞限位 |
| 碰撞几何 | 过于简化或重叠 | 穿模、异常接触力 |
| 足端位置 | 与几何不一致 | 逆运动学解算偏差 |
| 执行器参数 | 力矩上限 / 增益不符 | 跟踪能力被高估 |
| 传感器频率 | 与真机不一致 | 感知算法过拟合 |

建议先做三个基础实验：

1. 让机器人自由落体，检查落地是否稳定。
2. 固定身体，给单关节正弦指令，观察跟踪误差。
3. 让机器人原地站立，施加侧向扰动，观察恢复行为。

这三个实验能暴露大部分模型与执行器配置问题。

## 6. 可复现的实验设计

仿真实验应至少记录：

- 模型版本与 commit。
- 仿真器版本、物理参数、随机种子。
- 控制器参数与观测 / 动作定义。
- 初始状态与扰动序列。
- 评价指标：跟踪误差、能耗、恢复时间、成功率。

不要只保存“最好看的一次”。保存失败案例，往往更能说明策略的边界。

> 工程提示：把仿真当作“可重复的物理实验”，而不是“动画播放器”。每次修改参数都应能回答：我改变了什么，指标如何变化，为什么。

## 7. 接触与执行器建模

四足机器人的仿真可信度，很大程度上取决于接触与执行器模型。

接触模型至少涉及摩擦系数、接触刚度、阻尼与求解迭代次数。摩擦过低会让脚持续打滑，摩擦过高会让机器人“粘”在地面上，掩盖真实控制问题。接触刚度过高容易导致数值不稳定，过低则会让脚陷入地面。

执行器模型同样关键。真实电机有电流环、减速器、背隙与温升，仿真中常用“位置 / 速度 / 力矩源 + 增益 + 饱和”近似。若仿真中的力矩上限远高于真机，策略会学会一些真机做不到的动作。

建议做一次简单的参数敏感性实验：分别改变摩擦、质量与力矩上限，观察站立与行走指标的变化。如果控制器只在某一组“完美参数”下工作，它很可能无法迁移到真机。

## 8. 从单次实验到基准套件

一次成功的仿真只能说明“在这个初始状态下可行”。更可靠的做法是建立基准套件：

| 用例 | 目的 | 指标 |
| --- | --- | --- |
| 平地直行 | 基础跟踪能力 | 速度误差、姿态误差 |
| 转向 | 横向协调 | 偏航误差、横滚 |
| 斜坡 | 重力补偿 | 成功率、打滑率 |
| 侧向推力 | 抗扰动 | 恢复时间、最大倾角 |
| 关节限位 | 安全性 | 越限次数、饱和时间 |

每次修改控制器或模型，都跑同一套用例，并保存结果。这样你比较的是系统能力，而不是某一次演示的运气。

## 本节小结

- URDF、MJCF、USD 各有生态与能力边界，转换时要重点核对关节、惯量与碰撞。
- MuJoCo 适合接触与控制验证，Isaac Sim / Lab 适合高保真与大规模并行训练。
- 模型检查应覆盖质量、关节、碰撞、执行器与传感器。
- 可复现实验依赖版本、参数、种子与失败案例的完整记录。
